# Javis — Thai Voice Agent

เว็บและแอปมือถือสำหรับสนทนากับ AI ด้วยเสียงภาษาไทย ทำงานแบบเดียวกับผู้ช่วยเสียงของ Apple:
อุปกรณ์เป็นผู้ฟังและผู้พูดเอง ส่วน AI รับและตอบเป็นข้อความเท่านั้น

## หลักการทำงาน

1. **ฟัง** — ระบบรู้จำเสียงของอุปกรณ์แปลงคำพูดเป็นข้อความ และแสดงให้เห็นสดระหว่างพูด
2. **คิด** — ส่งเฉพาะข้อความไปที่ backend (`POST /api/chat`) ซึ่งสตรีมคำตอบจาก OpenAI กลับมาทีละส่วน และค้นเว็บให้เองเมื่อจำเป็น
3. **พูด** — เสียงภาษาไทยของอุปกรณ์อ่านคำตอบทีละประโยคทันทีที่ได้รับ แล้วกลับมาฟังต่อเอง

| ที่ทำงาน | ตัวฟัง | ตัวพูด |
|---|---|---|
| แอป iOS | Apple Speech framework | AVSpeechSynthesizer |
| แอป Android | SpeechRecognizer ของระบบ | TextToSpeech ของระบบ |
| Safari | Web Speech API (ระบบเสียงของ Apple) | เสียงของ Apple |
| Chrome / Edge | Web Speech API (ของผู้ผลิตเบราว์เซอร์) | เสียงที่ติดตั้งในเครื่อง |

ข้อจำกัด:
- Firefox ไม่รองรับการฟังเสียง ผู้ใช้ยังพิมพ์ข้อความได้
- ถ้าอุปกรณ์ไม่มีเสียงพูดภาษาไทย คำตอบจะแสดงเป็นข้อความอย่างเดียว (บน Windows ติดตั้งได้ที่ Settings → Time & language → Speech)
- บน Chrome และ Edge เสียงจะถูกส่งไปแปลงเป็นข้อความที่เซิร์ฟเวอร์ของผู้ผลิตเบราว์เซอร์

## ติดตั้งเป็นแอปหน้าต่างของตัวเอง

Javis ติดตั้งเป็นแอปแยกหน้าต่างได้โดยไม่ต้องผ่านสโตร์ เปิดจากหน้าจอหลักหรือเมนูเริ่มได้เหมือนโปรแกรมทั่วไป

- **Chrome / Edge (คอมพิวเตอร์และ Android):** เปิดเว็บ Javis แล้วกด ตั้งค่า → "ติดตั้งแอป Javis" หรือเลือก "ติดตั้งแอป" จากเมนูของเบราว์เซอร์
- **Safari บน iPhone / iPad:** กด "แชร์" แล้วเลือก "เพิ่มไปยังหน้าจอโฮม"

การติดตั้งต้องเปิดผ่าน HTTPS (หรือ `localhost` ตอนพัฒนา) ไอคอนแอปสร้างจาก `node scripts/generate-icons.mjs`

## แอปเดสก์ท็อป (เปิดเว็บและกรอกฟอร์มตามสั่ง)

แอปเดสก์ท็อปเป็นหน้าต่างของ Javis เองที่มีเบราว์เซอร์ในตัว จึงทำสิ่งที่เว็บแอปทำไม่ได้: เปิดหน้าเว็บในตัวแอปและกรอกฟอร์มของหน้านั้นตามที่ผู้ใช้สั่ง

```bash
npm run desktop
```

คำสั่งนี้ build หน้าเว็บ เปิด backend ในเครื่อง แล้วเปิดแอป ถ้ามี backend ที่ deploy แล้ว ให้ตั้ง `JAVIS_URL` เป็นที่อยู่นั้นแล้วรัน `npm run desktop:app` ตัวแอปเป็นเพียงเปลือก ไม่มี API key หรือความลับใดอยู่ในแอป

การใช้งาน:
1. สั่ง "เปิดเว็บ..." หน้าเว็บจะเปิดในตัวแอป แถบเสียงยังอยู่ด้านล่าง สลับดูบทสนทนาได้จากปุ่มด้านบน
2. สั่ง "กรอกชื่อ ... เบอร์ ..." Javis จะแสดงรายการ "ช่องไหน = ค่าอะไร" ให้ตรวจ
3. กด "ยืนยันและกรอก" หรือพูดว่า "ยืนยัน" จึงจะกรอกจริง แล้วผู้ใช้ตรวจและกดส่งฟอร์มเอง

กฎที่ Javis ทำตามเสมอ:
- **กรอกตามที่สั่งเท่านั้น:** กรอกเฉพาะช่องที่อยู่ในรายการที่ผู้ใช้ยืนยัน ช่องที่ AI เสนอแต่หน้าเว็บไม่มีจริงจะถูกทิ้งก่อนถึงผู้ใช้
- **ยืนยันทุกครั้ง:** ไม่มีการกรอกโดยไม่ผ่านการ์ดยืนยัน และคำถามใหม่จะยกเลิกรายการที่ยังไม่ได้ยืนยัน
- **ไม่ส่งฟอร์ม:** Javis ไม่กดปุ่มใดในหน้าเว็บ
- **ไม่แตะข้อมูลอ่อนไหว:** ช่องรหัสผ่าน บัตรชำระเงิน รหัส OTP ช่องซ่อน และช่องอ่านอย่างเดียว ไม่ถูกส่งให้ AI และกรอกไม่ได้
- **หน้าเปลี่ยนแล้วไม่กรอก:** ถ้าหน้าเว็บเปลี่ยนไปจากตอนที่เตรียมรายการ Javis จะไม่กรอกลงหน้าใหม่

ความเป็นส่วนตัวและข้อจำกัด:
- ระหว่างที่เปิดหน้าเว็บอยู่ ที่อยู่ ชื่อหน้า และชื่อช่องกรอกข้อมูลของหน้านั้นจะถูกส่งให้ AI พร้อมคำถาม (ไม่ส่งค่าที่กรอกอยู่ในช่อง)
- ระบบฟังเสียงของเบราว์เซอร์ใช้ในแอปเดสก์ท็อปไม่ได้ แอปจึงอัดเสียงแล้วส่งผ่าน backend ไปแปลงเป็นข้อความที่ OpenAI (`OPENAI_TRANSCRIBE_MODEL` ค่าเริ่มต้น `gpt-transcribe`) มีค่าใช้จ่ายต่อนาที และไม่มีข้อความขึ้นสดระหว่างพูด
- หน้าเว็บภายนอกรันแยกโปรเซส ขอสิทธิ์กล้อง ไมโครโฟน หรือตำแหน่งไม่ได้ และคุกกี้ของเว็บเหล่านั้นเก็บแยกจากตัวแอป
- ยังไม่มีไฟล์ติดตั้ง ต้องรันจากโฟลเดอร์โปรเจกต์ด้วยคำสั่งข้างบน

## หน้าจอ

หน้าจอเป็นแอปผู้ช่วยล้วน ๆ สามส่วน: แถบบน (สถานะ ตั้งค่า ผู้ใช้) พื้นที่บทสนทนา และแถบเสียงด้านล่างที่มีปุ่มเสียงปุ่มเดียวทำทุกจังหวะ (เริ่ม ส่ง พูดแทรก) คู่กับช่องพิมพ์

มีสองรูปแบบ เลือกได้ที่ ตั้งค่า → รูปแบบหน้าจอ และจำไว้ในอุปกรณ์:
- **โฮโลแกรม (ค่าเริ่มต้น):** จอ HUD พื้นมืดเรืองแสงฟ้า แกนกลางเป็นวงแหวนหมุนที่เปลี่ยนตามสถานะ (ฟัง = หมุนเร็วและสว่าง, คิด = สีเหลืองอำพัน, ตอบ = เต้นตามจังหวะ) แถบตัวเลขแสดงสถานะ ระบบ และเวลาจริง
- **เรียบ:** โทนเทากลางกับสีเขียวมรกต สว่างหรือมืดตามการตั้งค่าของอุปกรณ์

ทั้งสองรูปแบบใช้โครงหน้าจอเดียวกัน ต่างกันที่ตัวแปรสีใน `src/styles.css` (ธีมโฮโลแกรมอยู่ท้ายไฟล์) และภาพเคลื่อนไหวทั้งหมดหยุดเมื่ออุปกรณ์ตั้งค่าลดการเคลื่อนไหว

## ค้นเว็บและเปิดหน้าเว็บ

- **ค้นเว็บแล้วตอบเอง:** เมื่อคำถามต้องใช้ข้อมูลล่าสุด (ข่าว ราคา สภาพอากาศ) Javis จะค้นอินเทอร์เน็ตที่ฝั่ง backend ด้วยเครื่องมือค้นเว็บของผู้ให้บริการ AI แล้วตอบพร้อมแหล่งที่มาเป็นลิงก์ที่กดได้ เสียงพูดจะไม่อ่านลิงก์ออกมา OpenAI และ Claude ค้นเว็บอยู่แล้ว ปิดได้ด้วย `WEB_SEARCH_ENABLED=false` ส่วน Gemini ค้นได้เมื่อตั้งกุญแจของ Tavily (ฟรี 1,000 ครั้งต่อเดือน) หรือเปิดการค้นของ Google ซึ่งต้องเปิดการเรียกเก็บเงิน (ดูหัวข้อ "Google Gemini")
- **เปิดหน้าเว็บให้ดู:** สั่งด้วยเสียงหรือพิมพ์ เช่น "เปิดเว็บกรมอุตุฯ" หรือ "เปิดหน้าค้นหาร้านกาแฟใกล้ฉัน" Javis จะเปิดหน้าเว็บนั้นในแท็บใหม่หรือเบราว์เซอร์ของระบบ และแสดงลิงก์ไว้ในบทสนทนาเสมอ การค้นในเว็บที่ระบุ เช่น "ค้นหาเพลงใหม่ในยูทูบ" จะเปิดหน้าค้นหาของเว็บนั้น
- **คำสั่งให้ค้นหา:** คำพูดอย่าง "ค้นหา..." "ช่วยหาข้อมูล..." "หา...ให้หน่อย" หรือ "เสิร์ช..." ได้ผลเสมอ ถ้าค้นเว็บได้ Javis จะค้นแล้วตอบพร้อมแหล่งที่มา ถ้าค้นเว็บไม่ได้ (ยังไม่ได้ตั้งบริการค้นเว็บ หรือโควตาค้นหมด) Javis จะเปิดหน้าค้นหาของเรื่องนั้นให้ทันทีโดยไม่ถามกลับ ส่วนคำถามที่ต้องใช้ข้อมูลล่าสุดแต่ไม่ได้สั่งให้ค้น Javis จะบอกว่าไม่มีข้อมูลล่าสุดและถามก่อนว่าจะให้เปิดหน้าค้นหาไหม

ข้อควรรู้:
- **บนเว็บ เบราว์เซอร์จะบล็อกแท็บใหม่ที่ไม่ได้มาจากการแตะของผู้ใช้** คำสั่งเสียงจึงถูกบล็อกจนกว่าผู้ใช้จะอนุญาตป๊อปอัปให้เว็บของ Javis หนึ่งครั้ง (ใน Chrome: กดไอคอนป๊อปอัปถูกบล็อกที่ปลายแถบที่อยู่ แล้วเลือกอนุญาตเสมอ) เว็บขอสิทธิ์นี้เองไม่ได้ เมื่อถูกบล็อก Javis จะบอกด้วยเสียง ทำลิงก์เป็นปุ่มให้แตะเปิดได้ทันที และแสดงขั้นตอนของเบราว์เซอร์ที่ใช้อยู่ไว้ใต้ลิงก์ หลังอนุญาตแล้ว คำสั่งเสียงจะเปิดแท็บใหม่ได้เอง ส่วนแอปเดสก์ท็อปเปิดในเบราว์เซอร์ในตัวได้เลยโดยไม่ต้องตั้งค่า
- เปิดได้เฉพาะลิงก์ `http`/`https` และเปิดได้หนึ่งหน้าต่อคำตอบ
- ถ้าคำตอบรอบนั้นมีการอ่านเนื้อหาจากเว็บ Javis จะไม่เปิดหน้าให้อัตโนมัติ แต่แสดงเป็นลิงก์ให้ผู้ใช้กดเอง เพื่อกันไม่ให้เนื้อหาในเว็บหลอกให้เปิดหน้าอันตราย
- ผู้ให้บริการคิดค่าใช้จ่ายเพิ่มต่อการค้นหนึ่งครั้ง และโมเดลที่ตั้งไว้ต้องรองรับการค้นเว็บ (กับ Claude การค้นเว็บเปิดใช้อยู่แล้ว เว้นแต่ผู้ดูแลบัญชีปิดไว้)
- ถ้าโมเดลหรือบัญชีไม่รับการค้นเว็บ backend จะปิดการค้นเว็บเองจนกว่าจะรีสตาร์ต พร้อมพิมพ์คำเตือนใน log ผู้ใช้ยังได้คำตอบตามปกติ
- คำตอบที่ได้จากการค้นด้วย Google (Gemini) มีแถบ "คำค้นที่เกี่ยวข้อง" ของ Google อยู่ใต้คำตอบ ตามเงื่อนไขการใช้บริการของ Google กดแล้วเปิดหน้าผลค้นหาของ Google ในแท็บใหม่

## เริ่มใช้งานบนเว็บ

1. สร้าง `.env.local` จาก `.env.example` และตั้งกุญแจของผู้ให้บริการ AI หนึ่งราย: `ANTHROPIC_API_KEY`, `GEMINI_API_KEY` หรือ `OPENAI_API_KEY` (ดูหัวข้อ "ผู้ให้บริการ AI")
2. ติดตั้ง dependencies: `npm install`
3. รันทั้ง backend และเว็บ: `npm run dev`
4. เปิด `http://localhost:5173` และอนุญาตใช้ไมโครโฟน

API key อยู่เฉพาะ backend เบราว์เซอร์และแอปมือถือไม่เคยได้รับ key

## แอป Android / iOS

- Android: `npm run android`
- iOS: `npm run ios` (ต้องใช้ macOS และ Xcode)

Native iOS project อยู่ใน `ios/App/App.xcodeproj` และกำหนดสิทธิ์ไมโครโฟนกับการรู้จำเสียงแล้ว
ก่อน Archive ให้เปิดโปรเจกต์บน macOS เลือก Development Team และตรวจ Bundle Identifier
`com.fernclinic.javis` ใน Signing & Capabilities

ก่อน build สำหรับเครื่องจริง ให้ตั้ง `VITE_API_BASE_URL` เป็น URL HTTPS ของ backend ที่ deploy แล้ว จากนั้นรัน `npm run mobile:sync`

## ความจำ (Javis เรียนรู้จากผู้ใช้)

Javis จำเรื่องของผู้ใช้ข้ามบทสนทนาได้ และใช้ปรับคำตอบให้เข้ากับแต่ละคน

- **จำเอง:** เมื่อผู้ใช้บอกข้อมูลที่ควรจำ (ชื่อที่ให้เรียก งาน ความชอบ วิธีตอบที่ต้องการ) หรือสั่ง "จำไว้ว่า…" Javis จะจดไว้ และขึ้นป้าย "จำไว้แล้ว" ใต้คำตอบพร้อมปุ่มยกเลิก
- **ลืม:** สั่ง "ลืมเรื่อง…" หรือลบเองได้ที่ ตั้งค่า → ความจำของ Javis ซึ่งเพิ่มเองและลบทั้งหมดได้ด้วย
- **เก็บที่ไหน:** ในอุปกรณ์ของผู้ใช้เท่านั้น (localStorage) แยกตามผู้ใช้ที่เข้าสู่ระบบ ไม่มีฐานข้อมูลบนเซิร์ฟเวอร์ ความจำจึงไม่ตามไปอุปกรณ์อื่น และหายถ้าล้างข้อมูลของเบราว์เซอร์
- **ส่งไปไหน:** ทุกคำถามจะแนบความจำทั้งหมด (สูงสุด 50 เรื่อง เรื่องละไม่เกิน 200 ตัวอักษร) ไปให้ AI ใช้ตอบ

กฎความปลอดภัย:
- ไม่จำรหัสผ่าน รหัส OTP เลขบัตร และตัวเลขยาวตั้งแต่ 13 หลัก (backend ปฏิเสธแม้ AI จะขอจำ)
- ไม่จำอะไรหลังจากคำตอบรอบนั้นเริ่มอ่านเนื้อหาเว็บ เพื่อกันเนื้อหาเว็บแฝงคำสั่งให้จำสิ่งที่ผู้ใช้ไม่ได้บอก
- จำได้ไม่เกิน 3 เรื่องต่อหนึ่งคำตอบ และ AI ได้รับความจำในฐานะข้อมูล ไม่ใช่คำสั่ง

ข้อจำกัด: นี่คือการจำข้อมูลแล้วส่งให้โมเดลทุกครั้ง ไม่ใช่การฝึกโมเดลใหม่ ตัวโมเดลไม่ได้เปลี่ยน

## ตั้งค่าเสียง

ปุ่มตั้งค่าที่มุมขวาบนให้ผู้ใช้เลือกเสียงพูดภาษาไทยที่อุปกรณ์มี ปรับความเร็ว (0.6–1.6 เท่า) และกดทดลองฟังได้ ค่าที่เลือกเก็บไว้ในอุปกรณ์และมีผลกับประโยคถัดไปทันที

## ทดสอบและตรวจคุณภาพ

- `npm run lint` — ตรวจโค้ดด้วย ESLint
- `npm test` — ชุดทดสอบอัตโนมัติ (จังหวะสนทนา การตัดประโยค การเข้าสู่ระบบ และการตรวจข้อมูลฝั่ง backend)
- `npm run build` — ตรวจชนิดข้อมูลและ build

ทุก push และ pull request จะรันสามคำสั่งนี้พร้อมตรวจช่องโหว่ จากนั้น build Docker image แล้วรัน container จริงเพื่อตรวจว่า `/health` ตอบ หน้าเว็บถูกเสิร์ฟ `/api/chat` ปฏิเสธคำขอที่ไม่ได้เข้าสู่ระบบ และ container ไม่ได้รันด้วยสิทธิ์ root (`.github/workflows/ci.yml`)

## Deploy ด้วย Docker

```bash
docker build -t javis .
docker run -p 8787:8787 \
  -e OPENAI_API_KEY=... \
  -e ACCESS_CODES=light:รหัสของคุณไลท์ \
  -e SESSION_SECRET=... \
  -e TRUST_PROXY=1 \
  javis
```

Image ตั้ง `NODE_ENV=production` ให้แล้ว รันด้วยผู้ใช้ที่ไม่ใช่ root และมี health check ที่ `/health` ค่าลับทั้งหมดส่งเข้าทาง environment ตอนรัน ไม่ถูกฝังใน image

## Deploy ขึ้น Vercel (ลิงก์สาธารณะ)

เว็บสาธารณะของโปรเจกต์อยู่ที่ `https://javis-zeta.vercel.app` Vercel ดึง branch `main` ไป build เองทุกครั้งที่ push

Javis ต้องมีเซิร์ฟเวอร์ เพราะหน้าเว็บเรียก `/api/...` บนที่อยู่เดียวกัน บน Vercel แบ่งงานกันแบบนี้ (`vercel.json`)

- **หน้าเว็บ:** Vercel build ด้วย Vite แล้วเสิร์ฟไฟล์จาก `dist` เอง
- **เซิร์ฟเวอร์:** แอป Express ทั้งตัวรันเป็นฟังก์ชันเดียว (`api/index.ts`) ทุกคำขอ `/api/...` และ `/health` ถูกส่งมาที่ฟังก์ชันนี้ รันที่ภูมิภาคสิงคโปร์

### ค่าที่ต้องตั้งใน Vercel

ตั้งที่ Project → Settings → Environment Variables (Production) แล้วกด Redeploy เพราะค่าใหม่มีผลกับ deployment ถัดไปเท่านั้น

| ตัวแปร | จำเป็น | ค่า |
| --- | --- | --- |
| `ANTHROPIC_API_KEY`, `GEMINI_API_KEY` หรือ `OPENAI_API_KEY` | ใช่ อย่างใดอย่างหนึ่ง | กุญแจของผู้ให้บริการ AI: Gemini มีโควตาฟรี ส่วน Claude และ OpenAI ต้องมีเครดิต ดูหัวข้อ "ผู้ให้บริการ AI" |
| `ACCESS_CODES` | ไม่ | ผู้ใช้และรหัสเข้าใช้งาน เช่น `light:รหัสอย่างน้อย8ตัว` คั่นแต่ละคนด้วยจุลภาค **ถ้าไม่ตั้ง ใครมีที่อยู่เว็บก็ใช้ได้โดยไม่ต้องเข้าสู่ระบบ** |
| `SESSION_SECRET` | เมื่อตั้ง `ACCESS_CODES` | ข้อความสุ่มอย่างน้อย 32 ตัวอักษร สร้างด้วย `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` |
| `TAVILY_API_KEY` | ไม่ | กุญแจของ Tavily ให้ Gemini ค้นเว็บได้ฟรี 1,000 ครั้งต่อเดือน ตั้งแล้วค้นได้เลย ไม่ต้องเปิดการเรียกเก็บเงินกับ Google |
| `WEB_SEARCH_ENABLED` | ไม่ | `true` ให้ Gemini ค้นด้วย Google Search (ต้องเปิดการเรียกเก็บเงินของโปรเจกต์ก่อน) หรือ `false` ปิดการค้นเว็บของทุกราย ถ้าไม่ตั้ง OpenAI และ Claude ค้นเว็บ ส่วน Gemini ค้นเมื่อมีกุญแจของ Tavily |

ห้ามตั้งชื่อตัวแปรค่าลับให้ขึ้นต้นด้วย `VITE_` เพราะ Vite จะฝังค่านั้นลงในไฟล์หน้าเว็บ ใครเปิดเว็บก็อ่านได้ และไม่ต้องตั้ง `VITE_API_BASE_URL` เพราะหน้าเว็บกับเซิร์ฟเวอร์อยู่ที่อยู่เดียวกัน

**เปิดให้ใช้โดยไม่ต้องเข้าสู่ระบบ:** ลบตัวแปร `ACCESS_CODES` ออก (ไม่ใช่ใส่ค่าว่างหรือค่าที่ไม่ถูกรูปแบบ) แล้ว Redeploy ทุกคนที่มีที่อยู่เว็บจะใช้ได้ทันที และทุกคำตอบใช้เครดิตของบัญชี AI จึงควรตั้งเพดานค่าใช้จ่ายรายเดือนในบัญชีของผู้ให้บริการ AI และพิจารณาตั้ง `WEB_SEARCH_ENABLED=false` เพราะการค้นเว็บคิดค่าใช้จ่ายเพิ่มต่อครั้ง ตัวจำกัดความถี่ยังทำงานโดยนับตาม IP แต่บน Vercel กันได้ไม่เข้ม

ถ้าตั้งค่าผิด เซิร์ฟเวอร์จะบอกสาเหตุแทนการทำงานผิด ๆ: `ACCESS_CODES` ที่ใส่ไว้แต่ไม่มีรายการใดถูกรูปแบบ หรือมีรหัสแต่ไม่มี `SESSION_SECRET` จะปฏิเสธคำขอพร้อมข้อความ และเขียนสิ่งที่ต้องแก้ลง log ของฟังก์ชัน (ไม่เปิดให้ทุกคนใช้เองเมื่อพิมพ์รหัสผิดรูปแบบ) ส่วนกุญแจ API หรือเครดิตมีปัญหาจะเห็นได้ที่ `/health` ในช่อง `ai`

### สิ่งที่ต่างจากการรันเป็นเซิร์ฟเวอร์ (Docker)

ฟังก์ชันไม่มีกระบวนการค้างและอาจมีหลายตัวทำงานพร้อมกัน จึงมีข้อแลกเปลี่ยน

- **`SESSION_SECRET` จำเป็นเมื่อใช้รหัสเข้าใช้งาน** ไม่เช่นนั้นแต่ละตัวจะสุ่มกุญแจของตัวเอง โทเค็นใช้ข้ามตัวไม่ได้ ผู้ใช้จะหลุดจากระบบแบบสุ่ม เซิร์ฟเวอร์จึงปิดรับการเข้าสู่ระบบจนกว่าจะตั้งค่า
- **ตรวจบัญชี AI ตอนมีคนถามสถานะ** แทนการตั้งเวลา: ครั้งแรกที่มีคนเรียก `/health` หรือเปิดแอป และตรวจซ้ำเฉพาะตอนที่ยังมีปัญหา (ถี่สุดตาม `AI_RECHECK_SECONDS`)
- **ตัวจำกัดความถี่นับแยกตามตัวฟังก์ชัน** และเริ่มใหม่เมื่อฟังก์ชันถูกสร้างใหม่ จึงกันการใช้เกินได้ไม่เข้มเท่าเซิร์ฟเวอร์ตัวเดียว รหัสเข้าใช้งานควรยาวและเดายาก
- **เสียงที่อัดจากแอปเดสก์ท็อป** ส่งได้ไม่เกิน 4.5 MB ต่อครั้งตามเพดานของ Vercel (เสียงพูดปกติหนึ่งช่วงมีขนาดไม่ถึง 1 MB)
- `TRUST_PROXY` ไม่ต้องตั้ง เซิร์ฟเวอร์รู้เองว่าอยู่หลังตัวรับคำขอของ Vercel

หัวข้อความปลอดภัยของหน้าเว็บ (Content-Security-Policy และอื่น ๆ) ต้องเขียนไว้ใน `vercel.json` ด้วย เพราะไฟล์หน้าเว็บไม่ผ่านเซิร์ฟเวอร์ของเรา ชุดทดสอบ `server/vercelConfig.test.ts` ตรวจให้ว่าตรงกับที่เซิร์ฟเวอร์ใส่เอง ถ้าแก้นโยบายใน `server/security.ts` ต้องแก้ `vercel.json` ให้ตรงกัน

## ผู้ให้บริการ AI: Claude, Google Gemini หรือ OpenAI

Javis ใช้ผู้ให้บริการได้สามราย เลือกจากกุญแจที่ตั้งไว้ ไม่ต้องแก้โค้ด (`server/aiProvider.ts`)

| ตั้งค่า | ผลลัพธ์ |
| --- | --- |
| `OPENAI_API_KEY` อย่างเดียว | ใช้ OpenAI (ค่าเริ่มต้น) |
| `GEMINI_API_KEY` | ใช้ Google Gemini แม้จะยังมีกุญแจของ OpenAI ค้างอยู่ |
| `ANTHROPIC_API_KEY` | ใช้ Claude ของ Anthropic แม้จะยังมีกุญแจของรายอื่นค้างอยู่ |
| `AI_PROVIDER=claude`, `gemini` หรือ `openai` | บังคับเลือก ไม่ว่าจะตั้งกุญแจใดไว้ |

สิ่งที่ต่างกันระหว่างสามราย

| เรื่อง | Claude | Gemini | OpenAI |
| --- | --- | --- | --- |
| ค่าใช้จ่าย | คิดตามการใช้ ต้องมีเครดิตในบัญชี API | มีโควตาฟรีต่อนาทีและต่อวัน | คิดตามการใช้ ต้องมีเครดิต |
| โมเดลเริ่มต้น | `claude-haiku-5-5` (เปลี่ยนได้ด้วย `ANTHROPIC_CHAT_MODEL`) | `gemini-3.5-flash-lite` (เปลี่ยนได้ด้วย `GEMINI_CHAT_MODEL`) | `gpt-4.1-mini` (เปลี่ยนได้ด้วย `OPENAI_CHAT_MODEL`) |
| ค้นเว็บแล้วตอบเอง | ได้ | ได้เมื่อตั้งกุญแจของ Tavily (ฟรี) หรือเปิดการค้นของ Google (ต้องเปิดการเรียกเก็บเงิน) ถ้าไม่ตั้ง คำสั่งให้ค้นหาจะเปิดหน้าค้นหาให้แทน และคำถามที่ต้องใช้ข้อมูลล่าสุดจะได้คำตอบว่าไม่มีข้อมูลพร้อมข้อเสนอให้เปิดหน้าค้นหา | ได้ |
| เปิดหน้าเว็บ ความจำ กรอกฟอร์ม | ได้ | ได้ | ได้ |
| ฟังเสียงพูดในแอปเดสก์ท็อป | ไม่ได้ ต้องพิมพ์แทน | ไม่ได้ ต้องพิมพ์แทน | ได้ |
| ตรวจเครดิตตอนเริ่ม | ตรวจ | ไม่ตรวจ เพื่อไม่ใช้โควตาฟรี (เปิดได้ด้วย `AI_CREDIT_CHECK=true`) | ตรวจ |

เว็บและมือถือพูดได้ตามปกติกับทุกราย เพราะอุปกรณ์แปลงเสียงเป็นข้อความเอง ข้อจำกัดเรื่องเสียงมีเฉพาะแอปเดสก์ท็อป

### Claude ของ Anthropic

ขอกุญแจได้ที่ Claude Console (หน้า API keys) แล้วตั้งเป็น `ANTHROPIC_API_KEY` บัญชี API คิดค่าใช้จ่ายตามการใช้และต้องเติมเครดิตก่อน โดยแยกจากแพ็กเกจสมาชิกของแอป Claude (สมาชิกแบบ Pro หรือ Max ไม่รวมเครดิตของ API)

โมเดลที่เลือกได้ด้วย `ANTHROPIC_CHAT_MODEL` (ราคาต่อหนึ่งล้านโทเค็น ขาเข้า / ขาออก ตามที่ Anthropic ประกาศ ณ วันที่เขียนเอกสารนี้ ให้ตรวจราคาปัจจุบันก่อนใช้จริง)

| โมเดล | ราคา | เหมาะกับ |
| --- | --- | --- |
| `claude-haiku-5-5` (ค่าเริ่มต้น) | เริ่มที่ $0.10 / $0.50 | ราคาต่ำสุดและตอบเร็วที่สุด เหมาะกับผู้ช่วยเสียงที่ตอบสั้นและเว็บสาธารณะที่มีผู้ใช้มาก |
| `claude-sonnet-5-5` | $2 / $10 | สมดุลระหว่างคุณภาพกับราคา |
| `claude-opus-5-5` | $4 / $20 | คำตอบคุณภาพสูงสุดในสามรุ่นนี้ |

ราคาของ Haiku เป็นอัตราสำหรับคำขอที่ไม่เกิน 100,000 โทเค็น ซึ่งบทสนทนาของ Javis ปกติอยู่ในช่วงนี้

ข้อควรรู้

- **ระดับการคิด:** Claude คิดก่อนตอบ Javis ตั้งให้คิดน้อยที่สุด (`ANTHROPIC_EFFORT=low`) เพราะคำตอบถูกอ่านออกเสียงทันที ปรับเป็น `medium`, `high`, `xhigh`, `max` หรือ `default` (ให้โมเดลเลือกเอง) ได้ ยิ่งสูงยิ่งตอบช้าและใช้โทเค็นมากขึ้น
- **ค้นเว็บ:** ใช้เครื่องมือค้นเว็บของ Anthropic จำกัดไม่เกินสามครั้งต่อหนึ่งคำถามเพื่อไม่ให้ผู้ใช้รอนาน Anthropic คิด $10 ต่อการค้น 1,000 ครั้ง (ราว 1 เซนต์ต่อครั้ง) บวกค่าโทเค็นของผลค้นหา กับโมเดลรุ่นเล็ก ค่าค้นเว็บจึงมักสูงกว่าค่าโทเค็นของคำตอบหลายเท่า ถ้าต้องการคุมค่าใช้จ่ายให้ต่ำสุด ปิดได้ด้วย `WEB_SEARCH_ENABLED=false` การค้นเว็บเปิดใช้อยู่แล้ว เว้นแต่ผู้ดูแลบัญชีปิดไว้ใน Claude Console
- **เมื่อ Claude ปฏิเสธคำขอ:** ตัวกรองความปลอดภัยของ Claude อาจปฏิเสธคำถามบางแบบ (รวมถึงพลาดกับคำถามที่ไม่มีพิษภัยได้บ้าง) เมื่อถูกปฏิเสธ ผู้ใช้จะได้ยินประโยคขออภัยแทนการเงียบ ถ้าเลือกโมเดลรุ่นใหญ่ (Sonnet หรือ Opus) Javis จะขอให้ Anthropic ลองตอบด้วยโมเดลสำรองในคำขอเดียวกันก่อน (`fallbacks: "default"` ซึ่งยังเป็นความสามารถรุ่นเบต้า) โดยค่าใช้จ่ายของรอบสำรองคิดตามโมเดลสำรอง ส่วนโมเดลเริ่มต้น (Haiku) ไม่มีโมเดลสำรอง
- **ลดค่าใช้จ่ายของคำสั่งระบบ:** คำสั่งส่วนที่เหมือนกันทุกคำขอถูกทำเครื่องหมายให้ Anthropic แคชไว้ ข้อความถัดไปในบทสนทนาเดียวกัน (ภายในห้านาที) จึงเสียค่าส่วนนี้ถูกลงมาก ส่วนความจำของผู้ใช้ หน้าเว็บที่เปิดอยู่ และวันที่ อยู่นอกส่วนที่แคช
- **วันที่ปัจจุบัน:** Javis บอกวันที่ตามเวลาประเทศไทยให้ Claude ทุกคำขอ เพื่อให้รู้ว่าเรื่องใดควรค้นข้อมูลล่าสุดก่อนตอบ
- **ความเข้ากันได้ของโมเดล:** ถ้าโมเดลที่เลือกไม่รับตัวเลือกเสริม (ระดับการคิด โมเดลสำรอง) ไม่รับการค้นเว็บ หรือไม่รับข้อความระบบกลางบทสนทนา (ช่องทางที่ Javis ใช้แจ้งผลของความจำ มีเฉพาะโมเดลรุ่นใหม่) เซิร์ฟเวอร์จะลองใหม่หนึ่งครั้งแบบไม่มีสิ่งนั้น แล้วใช้แบบนั้นต่อไปพร้อมเตือนใน log ผู้ใช้ยังได้คำตอบ

การทำงานภายใน: Javis เรียก Claude ผ่าน SDK ทางการ `@anthropic-ai/sdk` ด้วย Messages API แบบสตรีม (`server/claudeClient.ts`) และมีตัวแปลงคำขอกับคำตอบเป็นรูปแบบกลางที่ส่วนอื่นของระบบใช้ (`server/claudeMessages.ts`) กติกาความปลอดภัยเดิมจึงใช้กับ Claude ครบ เช่น ไม่เปิดลิงก์เองและไม่จำอะไรหลังอ่านเนื้อหาจากเว็บ และตรวจอาร์กิวเมนต์ของเครื่องมือทุกตัวก่อนใช้

### Google Gemini

Gemini มีโควตาฟรีสำหรับโมเดลรุ่น Flash จึงใช้ทดลองหรือเปิดเว็บสาธารณะได้โดยไม่มีค่าใช้จ่าย ขอกุญแจได้ที่ Google AI Studio แล้วตั้งเป็น `GEMINI_API_KEY`

ข้อควรรู้ของโควตาฟรี

- เมื่อโควตาเต็ม ผู้ใช้จะเห็น "บริการ AI มีผู้ใช้งานหนาแน่น กรุณาลองใหม่ในอีกสักครู่" และกลับมาใช้ได้เองเมื่อโควตารอบใหม่มาถึง ตัวเลขโควตาเปลี่ยนได้ ให้ดูหน้า rate limits ของ Google
- Google ระบุว่าเนื้อหาที่ส่งผ่านโควตาฟรีอาจถูกใช้ปรับปรุงผลิตภัณฑ์ จึงไม่ควรใช้กับข้อมูลส่วนตัวหรือข้อมูลที่เป็นความลับ ถ้าต้องการความเป็นส่วนตัวให้ใช้แผนเสียเงิน หรือใช้ Claude หรือ OpenAI
- โมเดลของ Gemini มีขั้นคิดก่อนตอบ Javis ตั้งให้คิดน้อยที่สุด (`GEMINI_REASONING_EFFORT=minimal`) เพราะคำตอบถูกอ่านออกเสียงทันที ปรับเป็น `low`, `medium`, `high` หรือ `default` ได้

#### ค้นเว็บ (ต้องเปิดเอง)

Gemini ค้นเว็บได้สองทาง ค่าเริ่มต้นคือไม่ค้น ถ้าตั้งทั้งสองอย่าง Javis ใช้ Tavily

| | Tavily (ใช้กับกุญแจ Gemini แบบฟรีได้) | Google Search ของ Gemini |
| --- | --- | --- |
| ตั้งค่า | ตั้ง `TAVILY_API_KEY` อย่างเดียว | ตั้ง `WEB_SEARCH_ENABLED=true` |
| ค่าค้น | ฟรี 1,000 ครั้งต่อเดือน ไม่ต้องใช้บัตรเครดิต | ต้องเปิดการเรียกเก็บเงินของโปรเจกต์: ฟรี 5,000 คำค้นต่อเดือน เกินจากนั้น $14 ต่อ 1,000 คำค้น |
| ค่าโทเค็นของ Gemini | ฟรีตามโควตาฟรี | คิดตามการใช้ เช่น `gemini-3.5-flash-lite` $0.30 / $2.50 ต่อหนึ่งล้านโทเค็น (ขาเข้า / ขาออก) |
| แหล่งที่มาที่ผู้ใช้เห็น | ลิงก์จริงของเว็บที่พบ | ลิงก์ส่งต่อของ Google พร้อมแถบคำค้นของ Google |

ตัวเลขทั้งหมดเป็นของวันที่เขียนเอกสารนี้ (พฤศจิกายน 2026) ให้ตรวจหน้าราคาของแต่ละรายก่อนใช้จริง

**กุญแจ Gemini แบบฟรีค้นด้วย Google ไม่ได้:** ตรวจกับกุญแจที่สร้างใหม่เมื่อ 12 พฤศจิกายน 2026 รุ่น 2.5 Flash และ 2.5 Flash-Lite ซึ่งหน้าราคาของ Google ระบุว่าโควตาฟรีค้นได้ ตอบว่าไม่เปิดให้ผู้ใช้ใหม่แล้ว (404) ส่วนรุ่น 3 ขึ้นไปตอบว่าเกินโควตา (429) เพราะการค้นต้องเปิดการเรียกเก็บเงิน

##### ค้นด้วย Tavily

สมัครที่ tavily.com แล้วตั้งกุญแจเป็น `TAVILY_API_KEY` การตั้งกุญแจคือการเปิดการค้น ไม่ต้องตั้ง `WEB_SEARCH_ENABLED` เพิ่ม (ปิดได้ด้วย `WEB_SEARCH_ENABLED=false`)

โมเดลสนทนาตอบตามปกติพร้อมเครื่องมือของ Javis ครบ เมื่อคำถามต้องใช้ข้อมูลล่าสุด โมเดลจะขอค้นผ่านเครื่องมือ `search_web` เซิร์ฟเวอร์ค้นด้วย Tavily (`server/webSearch.ts`) แล้วส่งผลค้นไม่เกินห้ารายการให้โมเดลใช้ตอบ ผู้ใช้เห็นแหล่งที่มาเป็นลิงก์ของเว็บที่พบ

- คำถามทั่วไปใช้หนึ่งคำขอถึง Gemini ส่วนคำถามที่ต้องค้นใช้สองคำขอถึง Gemini กับหนึ่งเครดิตของ Tavily
- คำค้นถูกส่งให้ Tavily และเนื้อหาของผลค้นถูกส่งให้ Gemini ในฐานะข้อมูล โมเดลถูกสั่งไม่ให้ทำตามคำสั่งใดในนั้น และขั้นตอบจากผลค้นไม่มีเครื่องมือใดให้เรียก
- เมื่อโควตาของ Tavily หมด Javis ตอบโดยไม่ค้นและพักการค้น 60 นาที ถ้ากุญแจใช้ไม่ได้จะปิดการค้นจนกว่าจะรีสตาร์ตพร้อมเตือนใน log ส่วนเหตุขัดข้องชั่วคราวจะลองค้นใหม่ในคำถามถัดไป

##### ค้นด้วย Google Search

ตั้ง `WEB_SEARCH_ENABLED=true` กับกุญแจของโปรเจกต์ที่เปิดการเรียกเก็บเงินแล้ว Javis จะส่งเครื่องมือค้นของ Google ไปกับคำขอของโมเดลสนทนา ซึ่งต้องเป็น Gemini 3 ขึ้นไป คำถามหนึ่งข้อจึงใช้คำขอเดียว ควรตั้งเพดานค่าใช้จ่ายของโปรเจกต์ไว้ เพราะ Google นับตามจำนวนคำค้นที่โมเดลส่งจริง และคำถามหนึ่งข้ออาจใช้มากกว่าหนึ่งคำค้น

- **โมเดลค้นแยก:** ตั้ง `GEMINI_SEARCH_MODEL` เป็นโมเดลอื่นได้ Javis จะค้นเป็นขั้นแยก: โมเดลสนทนาขอค้นผ่าน `search_web` แล้วเซิร์ฟเวอร์ส่งบทสนทนาไปยังโมเดลค้นพร้อมเครื่องมือค้นของ Google อย่างเดียว ทางนี้มีไว้สำหรับโปรเจกต์เก่าที่ยังใช้รุ่น 2.5 ได้ ซึ่งโควตาฟรีรวมการค้น 500 ครั้งต่อวัน แต่ใช้การค้นร่วมกับเครื่องมืออื่นในคำขอเดียวไม่ได้
- **แถบคำค้นของ Google:** เงื่อนไขการใช้ของ Google กำหนดให้แสดง "คำค้นที่เกี่ยวข้อง" (Search Suggestions) คู่กับคำตอบที่ได้จากการค้น ตามหน้าตาที่ Google ให้มา Javis จึงแสดงแถบนี้ใต้คำตอบ และลิงก์เปิดหน้าของ Google โดยตรงในแท็บใหม่ แถบนี้เป็น HTML จากนอกแอป หน้าเว็บจึงสร้างใหม่เฉพาะองค์ประกอบที่อนุญาต (ไม่มีสคริปต์ ไม่มีรูปจากภายนอก ลิงก์ต้องเป็น `http`/`https`) และแยกไว้ใน shadow root ของตัวเอง (`src/services/searchSuggestions.ts`) โดยไม่ต้องผ่อนนโยบายความปลอดภัยของหน้าเว็บ
- **แหล่งที่มา:** ลิงก์แหล่งที่มาเป็นลิงก์ส่งต่อของ Google (`vertexaisearch.cloud.google.com`) ป้ายของลิงก์จึงใช้ชื่อเว็บที่ Google ให้มา
- **ความเป็นส่วนตัว:** Google เก็บคำถามและคำตอบของคำขอที่ค้นด้วย Google ไว้ 30 วันเพื่อตรวจแก้ปัญหาของระบบ ส่วน Javis ไม่ฝากบทสนทนาไว้กับ Google (`store: false`) และไม่บันทึกผลค้นหรือแถบคำค้นลงอุปกรณ์
- **เมื่อค้นไม่ได้:** ถ้า Google ปฏิเสธการค้น (เช่น โปรเจกต์ไม่มีสิทธิ์ใช้โมเดลค้น หรือโมเดลที่เลือกใช้กับเครื่องมือค้นไม่ได้) เซิร์ฟเวอร์จะตอบโดยไม่ค้นแทน แล้วปิดการค้นจนกว่าจะรีสตาร์ต พร้อมเตือนใน log ถ้า Google ตอบว่าโควตาเต็ม (HTTP 429 ซึ่งเป็นคำตอบที่กุญแจแบบฟรีได้รับด้วย) จะพักการค้น 60 นาทีแล้วลองใหม่เอง ผู้ใช้ยังได้คำตอบทุกกรณี
- **โมเดลที่ใช้ได้:** การใช้เครื่องมือค้นของ Google ร่วมกับเครื่องมือของ Javis (เปิดหน้าเว็บ ความจำ) ในคำขอเดียวกัน มีเฉพาะ Gemini 3 ขึ้นไป และ Google ยังจัดเป็นความสามารถรุ่นทดลอง ถ้าโมเดลที่เลือกไม่รับระดับการคิดที่ตั้งไว้ตอนค้นเว็บ เซิร์ฟเวอร์จะลองใหม่หนึ่งครั้งโดยยังค้นเว็บอยู่ แล้วใช้ค่าเริ่มต้นของโมเดลกับคำขอที่ค้นเว็บต่อไปพร้อมเตือนใน log

ข้อควรรู้ของทั้งสองทาง

- **วันที่ปัจจุบัน:** Javis บอกวันที่ตามเวลาประเทศไทยให้ Gemini ทุกคำขอที่ค้นเว็บได้ เพื่อให้รู้ว่าเรื่องใดควรค้นข้อมูลล่าสุดก่อนตอบ
- **คำตอบที่มีทั้งการค้นและการเปิดหน้าเว็บ:** หน้าเว็บจะแสดงเป็นลิงก์ให้ผู้ใช้กดเอง ไม่เปิดให้อัตโนมัติ ตามกติกาเดิมของคำตอบที่อ่านเนื้อหาจากเว็บ
- **ยังไม่ได้ทดสอบกับบริการจริงทุกทาง:** ทางสนทนา เครื่องมือของ Javis และการขอค้นผ่าน `search_web` ทดสอบกับ Gemini จริงแล้ว ส่วนคำตอบจากการค้นของ Google และของ Tavily ทดสอบกับตัวจำลองตามเอกสารของแต่ละราย

การทำงานภายใน: Javis คุยกับ OpenAI ด้วย Responses API ส่วน Gemini ใช้รูปแบบ Chat Completions เซิร์ฟเวอร์จึงมีตัวแปลงคำขอและคำตอบระหว่างสองรูปแบบ (`server/chatCompletions.ts`) ทางนี้ไม่มีเครื่องมือค้นของ Google คำขอที่ค้นด้วย Google จึงใช้ Interactions API ของ Gemini โดยตรงผ่านตัวแปลงอีกตัว (`server/geminiInteractions.ts`) ส่วนอื่นของระบบทำงานเหมือนกันทุกราย กติกาความปลอดภัยเดิมจึงใช้ครบ เช่น ไม่เปิดลิงก์เองและไม่จำอะไรหลังอ่านเนื้อหาจากเว็บ

**ช่องวินิจฉัยของผู้ดูแล:** สาเหตุที่ผู้ให้บริการปฏิเสธคำขออยู่ใน log ของเซิร์ฟเวอร์ ถ้าเปิด log ไม่สะดวก ตั้ง `DIAGNOSTIC_TOKEN_SHA256` เป็นค่าแฮช SHA-256 ของรหัสที่ตั้งเอง แล้วส่งคำขอ `POST /api/chat` ที่แนบรหัสนั้นในช่อง `diagnose` คำตอบจะมีเหตุการณ์ `diagnostic` ต่อท้าย บอกคำขอที่เซิร์ฟเวอร์ส่งไปยังผู้ให้บริการในรอบนั้น สถานะ เวลาที่ใช้ ข้อความของผู้ให้บริการที่ปิดบังสิ่งที่ดูเหมือนกุญแจแล้ว เครื่องมือที่ AI เรียก รูปร่างของสตรีมจากโมเดลสนทนา (มีข้อความ เรียกเครื่องมือชื่ออะไร จบด้วยเหตุผลใด โดยไม่มีเนื้อหาของคำตอบ) และรหัสคอมมิตของรุ่นที่กำลังทำงานเมื่อโฮสต์บอกไว้ คำขอที่ไม่มีรหัสไม่ได้ข้อมูลนี้ และแอปไม่เคยส่งช่องนี้

เซิร์ฟเวอร์ปรับคำขอให้เข้ากับข้อบังคับของ Gemini เอง: จัดบทสนทนาให้เริ่มที่ผู้ใช้และสลับผู้พูดทุกข้อความ (ข้อความของผู้พูดคนเดียวกันที่ติดกันถูกรวมเป็นข้อความเดียว) และถ้าโมเดลที่เลือกไม่รับระดับการคิดที่ตั้งไว้ จะลองใหม่หนึ่งครั้งโดยไม่กำหนด แล้วใช้ค่าเริ่มต้นของโมเดลต่อไปพร้อมเตือนใน log

ถ้าอยากได้คำตอบที่ฉลาดขึ้นและยอมให้โควตาต่อวันน้อยลง ตั้ง `GEMINI_CHAT_MODEL=gemini-3.8-flash` ถ้าชื่อโมเดลใช้ไม่ได้ `/health` จะรายงาน `chat` เป็น `model`


## การเข้าสู่ระบบ

ผู้ใช้แต่ละคนมีรหัสเข้าใช้งานของตัวเอง ตั้งที่ `ACCESS_CODES` ของ backend ในรูปแบบ `ชื่อ:รหัส,ชื่อ:รหัส`

- กรอกรหัสถูกต้องแล้วได้โทเค็นแบบลงลายเซ็น อายุ 30 วัน เก็บไว้ในอุปกรณ์ และแนบไปกับทุกคำขอสนทนา
- **เพิกถอนสิทธิ์:** ลบหรือเปลี่ยนรหัสของผู้ใช้ใน `ACCESS_CODES` แล้วรีสตาร์ต โทเค็นเดิมของคนนั้นใช้ไม่ได้ทันที
- **กันการเดารหัส:** กรอกผิดได้ 10 ครั้งต่อ IP ต่อ 15 นาที
- ตั้ง `SESSION_SECRET` (อย่างน้อย 32 ตัวอักษร) ไว้ด้วย มิฉะนั้นผู้ใช้ต้องเข้าสู่ระบบใหม่ทุกครั้งที่ backend รีสตาร์ต
- ถ้าไม่ได้ตั้ง `ACCESS_CODES`: ใช้งานได้โดยไม่ต้องเข้าสู่ระบบ ทั้งตอนพัฒนาและบนเครื่องใช้งานจริง ซึ่งบนเว็บสาธารณะหมายถึงใครก็ใช้ได้และใช้เครดิตของบัญชี AI ได้ เซิร์ฟเวอร์จะเตือนเรื่องนี้ใน log ตอนเริ่ม
- ถ้าตั้ง `ACCESS_CODES` ไว้แต่ไม่มีรายการใดถูกรูปแบบ (เช่น ใส่แต่รหัสโดยไม่มี `ชื่อ:` นำหน้า): backend จะปฏิเสธคำขอทั้งหมดและบอกสิ่งที่ต้องแก้ใน log โดยไม่พิมพ์ค่าที่ใส่มา เพราะอาจเป็นรหัสจริง

## ความเป็นส่วนตัวของเสียง

บนแอป iOS ถ้าเครื่องมีโมเดลรู้จำเสียงภาษาไทยในตัว Javis จะแปลงเสียงเป็นข้อความภายในเครื่อง เสียงไม่ถูกส่งออกจากอุปกรณ์ และหน้าจอจะแจ้งให้ผู้ใช้ทราบ ถ้าเครื่องไม่รองรับหรือโมเดลใช้ไม่ได้ จะถอยไปใช้ระบบรู้จำเสียงออนไลน์ของ Apple โดยอัตโนมัติ

## ความปลอดภัยของ backend

- **จำกัดต้นทาง:** `/api` รับคำขอจากเว็บที่เสิร์ฟจาก backend เดียวกัน แอป Capacitor และรายการใน `ALLOWED_ORIGINS` เท่านั้น เว็บอื่นได้ 403
- **จำกัดความถี่:** `/api/chat` และ `/api/transcribe` รับได้อย่างละ `CHAT_RATE_LIMIT_MAX` ครั้งต่อผู้ใช้ต่อ 10 นาที (ค่าเริ่มต้น 100) เกินแล้วได้ 429
- **จำกัดขนาด:** รับประวัติได้ไม่เกิน 24 ข้อความ ข้อความละไม่เกิน 2,000 ตัวอักษร
- **Security headers:** ตั้ง CSP, HSTS และ Permissions-Policy ให้อัตโนมัติ
- **ข้อผิดพลาด:** ตอบเป็น JSON เสมอ ไม่ส่ง stack trace ออกไป
- **ข้อผิดพลาดจากบริการ AI:** แยกสาเหตุให้ผู้ใช้รู้ว่าต้องทำอะไรต่อ เช่น เครดิตของบัญชีหมด กุญแจ API ใช้ไม่ได้ โมเดลที่ตั้งค่าไว้ไม่พร้อมใช้ หรือผู้ใช้หนาแน่น (`server/upstreamError.ts`) โดยส่งให้ผู้ใช้เฉพาะข้อความที่เขียนไว้เอง ไม่ส่งข้อความดิบของต้นทาง ส่วน log ของเซิร์ฟเวอร์บันทึกรหัสข้อผิดพลาด และเฉพาะเมื่อต้นทางปฏิเสธรูปแบบของคำขอ (รหัส 400) จะบันทึกข้อความของต้นทางที่ตัดให้สั้นและปิดบังสิ่งที่ดูเหมือนกุญแจแล้ว เพื่อให้ผู้ดูแลรู้ว่าต้องแก้การตั้งค่าใด

ก่อน deploy ให้ตั้ง `NODE_ENV=production` และถ้า backend อยู่หลัง reverse proxy ให้ตั้ง `TRUST_PROXY` เป็นจำนวนชั้นของ proxy มิฉะนั้นผู้ใช้ทุกคนจะถูกนับเป็น IP เดียวกัน

ข้อจำกัด: ตัวนับความถี่เก็บในหน่วยความจำของเครื่องเดียว จึงรีเซ็ตเมื่อรีสตาร์ตและไม่แชร์ระหว่างหลายเครื่อง ส่วนโทเค็นเก็บใน localStorage ของอุปกรณ์ ผู้ใช้ควรออกจากระบบเมื่อใช้เครื่องร่วมกับผู้อื่น

## ตรวจสุขภาพ backend

`GET http://localhost:8787/health`

```json
{ "ok": true, "service": "javis-voice-agent", "ai": { "status": "ok", "chat": "ok", "transcribe": "ok", "checkedAt": "2026-11-11T10:17:49.241Z" } }
```

- `ok` บอกว่าเซิร์ฟเวอร์ยังทำงาน บัญชี AI มีปัญหาไม่ทำให้เป็น `false` เพราะการรีสตาร์ตไม่ช่วยแก้
- `ai.status` คือ `ok`, `degraded` (ต้องให้ผู้ดูแลแก้) หรือ `unknown` (ยังไม่รู้)
- `ai.chat` และ `ai.transcribe` คือสถานะของการสนทนาและการแปลงเสียง:

| ค่า | ความหมาย | วิธีแก้ |
| --- | --- | --- |
| `ok` | ใช้งานได้ | |
| `quota` | เครดิตของบัญชี AI หมด | เติมเครดิต |
| `auth` | ไม่ได้ตั้งกุญแจของผู้ให้บริการ AI หรือกุญแจถูกปฏิเสธ | แก้ค่าใน environment (`ANTHROPIC_API_KEY`, `GEMINI_API_KEY` หรือ `OPENAI_API_KEY`) |
| `model` | ไม่พบโมเดลที่ตั้งค่าไว้ หรือบัญชีไม่มีสิทธิ์ใช้โมเดลนั้น | แก้ชื่อโมเดล เช่น `ANTHROPIC_CHAT_MODEL`, `OPENAI_CHAT_MODEL` หรือ `OPENAI_TRANSCRIBE_MODEL` |
| `unsupported` | ผู้ให้บริการที่ใช้อยู่ไม่มีบริการนี้ (การแปลงเสียงของ Claude และ Gemini) | ไม่ต้องแก้ แอปเดสก์ท็อปให้พิมพ์แทน |
| `unreachable` | ตรวจไม่ได้เพราะติดต่อบริการ AI ไม่สำเร็จ | ตรวจเครือข่ายของเซิร์ฟเวอร์ |
| `unchecked` | ยังไม่ได้ตรวจ | |

### ตรวจบัญชี AI ตอนเริ่มเซิร์ฟเวอร์

ทุกครั้งที่เริ่ม เซิร์ฟเวอร์จะตรวจบัญชี AI เบื้องหลัง (ไม่หน่วงการเริ่มและไม่ทำให้เซิร์ฟเวอร์ล้ม) แล้วเขียนผลลง log ขึ้นต้นด้วย `ตรวจบัญชี AI:` เพื่อให้ผู้ดูแลรู้ปัญหาก่อนผู้ใช้เจอ (`server/aiAccount.ts`)

1. **กุญแจ API และโมเดล** ถามบริการ AI ว่ามีโมเดลที่ตั้งไว้ไหม ไม่มีค่าใช้จ่าย และเตือนถ้าโมเดลมีกำหนดปิดให้บริการ พร้อมจำนวนวันที่เหลือ
2. **เครดิต** ส่งคำขอสั้นที่สุดหนึ่งครั้ง (ราว 20 โทเค็น) ปิดได้ด้วย `AI_CREDIT_CHECK=false`

หลังจากนั้นสถานะจะอัปเดตจากผลของคำขอจริงของผู้ใช้โดยไม่มีค่าใช้จ่ายเพิ่ม เช่น เครดิตหมดระหว่างวันจะเปลี่ยนเป็น `quota` ทันที และกลับเป็น `ok` เองเมื่อมีคำตอบสำเร็จครั้งแรกหลังเติมเครดิต โดยไม่ต้องรีสตาร์ต ส่วนข้อผิดพลาดชั่วคราว (ผู้ใช้หนาแน่น ต้นทางขัดข้อง) ไม่เปลี่ยนสถานะ

ระหว่างที่สถานะยังไม่ปกติ เซิร์ฟเวอร์จะตรวจซ้ำเองทุก 5 นาที (ปรับได้ด้วย `AI_RECHECK_SECONDS`) สถานะจึงกลับมาเป็น `ok` หลังผู้ดูแลแก้ไข แม้ยังไม่มีผู้ใช้ส่งข้อความ และเขียน log เฉพาะตอนที่สถานะเปลี่ยน ตอนใช้งานได้ตามปกติจะไม่ตรวจซ้ำ ข้อยกเว้น: ถ้าตั้ง `AI_CREDIT_CHECK=false` การตรวจซ้ำจะไม่รู้ว่าเครดิตกลับมาแล้ว สถานะ `quota` จะหายเมื่อมีคำตอบสำเร็จครั้งแรกเท่านั้น

### แถบแจ้งเตือนในแอป

แอปถามสถานะเดียวกันนี้จาก `GET /api/status` (ข้อมูลหมวดกว้างชุดเดียวกับ `/health` แต่อยู่ใต้ `/api` เพื่อให้แอปมือถือเรียกข้ามต้นทางได้) แล้วแสดงแถบแจ้งเตือนใต้หัวจอตั้งแต่เปิดแอป ผู้ใช้จึงรู้ก่อนจะพูดแล้วไม่ได้คำตอบ (`src/components/ServiceBanner.tsx`, `src/services/aiStatusStore.ts`)

- **Javis ตอบไม่ได้** (`chat` เป็น `quota`, `auth` หรือ `model`): แถบสีแดงบอกสาเหตุและสิ่งที่ต้องทำ ป้ายสถานะบนหัวจอเปลี่ยนเป็น "AI ใช้งานไม่ได้"
- **ฟังเสียงพูดไม่ได้** (`transcribe` มีปัญหาแต่ `chat` ยังใช้ได้): แถบสีเหลืองชวนให้พิมพ์แทน แสดงเฉพาะแอปเดสก์ท็อป เพราะเว็บและมือถือแปลงเสียงบนอุปกรณ์เอง
- แถบไม่ปิดกั้นการพิมพ์หรือไมโครโฟน และหายเองเมื่อบริการกลับมา: ทันทีหลังคำตอบสำเร็จครั้งแรก เมื่อกด "ตรวจอีกครั้ง" หรือภายในหนึ่งนาทีจากการถามซ้ำอัตโนมัติ (ถามซ้ำเฉพาะตอนที่แถบแสดงอยู่และหน้าจอเปิดอยู่)
- ถ้าเครดิตหมดระหว่างใช้งาน แถบจะขึ้นเองหลังคำขอที่ล้มเหลว โดยไม่ต้องโหลดหน้าใหม่

`/health` และ `/api/status` เปิดให้เรียกได้โดยไม่ต้องเข้าสู่ระบบ เพื่อให้เครื่องมือเฝ้าระบบใช้ได้ และให้แอปถามได้โดยไม่ผูกกับเซสชันของผู้ใช้ จึงรายงานเฉพาะหมวดกว้าง ๆ ข้างต้น ไม่มีข้อความ รหัสข้อผิดพลาด หรือชื่อโมเดลจากต้นทาง ปิดการตรวจทั้งหมดได้ด้วย `AI_STARTUP_CHECK=false`

ข้อจำกัด: ถ้าตั้ง `OPENAI_BASE_URL` ไปยังบริการที่ไม่มีเส้นทาง `/models/{ชื่อโมเดล}` ผลตรวจโมเดลจะคลาดเคลื่อน ให้ปิดด้วย `AI_STARTUP_CHECK=false`
